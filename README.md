# SMS Test Task

Решение тестового задания для позиции Middle Fullstack C# Developer. Репозиторий содержит две клиентские библиотеки для SMS API, консольное приложение для работы с меню и заказами, а также WPF-приложение для просмотра и изменения пользовательских переменных среды.

## Состав решения

| Проект | Назначение |
| --- | --- |
| `Sms.Shared` | Общие модели, контракты SMS-клиента и исключения. |
| `Sms.Client.Http` | HTTP-клиент с Basic-аутентификацией и JSON-протоколом. |
| `Sms.Client.Grpc` | Альтернативная реализация клиента на gRPC. |
| `Sms.ConsoleApp` | Получает меню через HTTP, сохраняет его в PostgreSQL, принимает заказ по артикулам и отправляет его на сервер. |
| `Sms.WpfApp` | Показывает и изменяет пользовательские переменные среды Windows. |

Для каждого основного компонента в каталоге `tests` расположен отдельный проект с тестами на xUnit.

## Стек

- .NET 8;
- WPF и ReactiveUI;
- PostgreSQL, Entity Framework Core и Npgsql;
- Autofac для регистрации зависимостей;
- NLog для файлового логирования;
- xUnit для тестов.

## Запуск

Потребуется .NET 8 SDK. Для WPF-приложения необходима Windows, для консольного приложения — доступный экземпляр PostgreSQL и SMS API, соответствующий протоколу из задания.

Перед запуском нужно проверить настройки:

- `src/Sms.ConsoleApp/appsettings.json` — строка подключения к PostgreSQL, адрес SMS API, логин, пароль и таймаут;
- `src/Sms.WpfApp/appsettings.json` — имена переменных среды, значения по умолчанию и комментарии.

```powershell
dotnet restore
dotnet run --project src/Sms.ConsoleApp
dotnet run --project src/Sms.WpfApp
```

При первом запуске консольного приложения EF Core применяет миграции и при необходимости создаёт базу данных. Для создания отсутствующей базы пользователь PostgreSQL должен иметь право `CREATEDB`.

Консольное приложение принимает заказ в формате:

```text
A1004292:1;A1004293:0.408
```

Пользователь вводит артикулы блюд, а перед отправкой они преобразуются во внутренние идентификаторы, полученные от API.

## Тесты

Запуск всех тестов решения:

```powershell
dotnet test
```

Тестами покрыты HTTP- и gRPC-клиенты, разбор заказа, основной сценарий консольного приложения, загрузка настроек и логика WPF ViewModel.

## Логи

Логи создаются рядом с исполняемыми файлами и разделяются по дням:

```text
test-sms-console-app-yyyyMMdd.log
test-sms-wpf-app-yyyyMMdd.log
```

Формат и уровень логирования настраиваются отдельно для каждого приложения в `NLog.config`.

## Примечания

- Консольное приложение подключено к HTTP-реализации клиента; gRPC-проект оставлен как готовая альтернативная DLL.
- Autofac и ReactiveUI, в целом, являются небольшим оверхедом в данной задачи, но это очень классные инструменты в реальной разработке, поэтому я решил их внедрить
